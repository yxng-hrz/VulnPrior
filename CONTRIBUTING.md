# Contributing

## Development workflow

1. Create a feature branch.
2. Add or update tests.
3. Run `pytest -q`.
4. Keep risk-scoring changes explainable and documented.
5. Open a pull request with the business reason for the change.

## Commit style

Examples:

```text
feat: add risk preview endpoint
fix: prevent duplicate asset findings
test: cover compensating control scoring
docs: explain business risk model
```
